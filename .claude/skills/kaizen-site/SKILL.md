# 改善の1周(注目銘柄メモだけの部分)

共通の手順(`TakahiroUkai/site-ops` の `.claude/skills/kaizen-loop/SKILL.md`)と一緒に使う。

## 基本

- 項目の接頭辞: `SM`(司令塔の `site` は `stock`)
- 既定ブランチ: `main`。公開URL: https://takahiroukai.github.io/stock-memo2/
- 改善の曜日: 木曜
- このリポジトリの `data/analytics.json` は、GitHub Actions が毎朝更新する(4サイト分のアクセス数)。改善の回では読むだけで、変えない。

## ユーザー役の読者像

`style.md` の「想定読者」になりきる。通勤中にスマホで、トップページ → 銘柄の記事を1本 → 用語の説明・クイズ、の順に3分ほどで読み、「何の会社か、数字、気をつける点が先に分かるか」「用語でつまずかないか」「表やグラフが横にはみ出さないか」を確かめる。

## 事業推進役の観点(共通の観点に加えて)

- 過去の銘柄を探しやすいか、比べやすいか。
- 用語が分からない人が置いていかれないか。
- ほかのサイト(稼ぎのトリセツのインデックス投資など)への自然な導線になるか。

## 直してよい範囲

- `build.py` のページの組み立て、CSS、一覧・グラフ・用語の見せ方、既存の記事の分かりにくい文。
- 直さない: `data/analytics.json`、`analytics/`、`.github/workflows/`、`RULES.md` と `style.md`(変えたほうがよいときは「要確認」の項目にする)。売買を勧める表現、専門家名、共有・評価の話を公開ページに入れない。数字を書き換えるときは、時点と出典を確かめる。

## 確かめ方

1. `python3 build.py`(このサイトの検査は build.py の中にある。止まったら直す)
2. 変えたページを、スマホ幅(iPhone 13 相当)のスクリーンショットで見て、崩れ・横へのはみ出しがないこと。
3. `grep` で、公開ページに売買を勧める表現・専門家名が無いことを確かめる。
